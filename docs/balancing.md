# 数值表维护

唯一源是 `design/数值策划.xlsx`。蓝字表示可调整输入；灰色ID和名称表示与 `js/content.js` 对应的引用信息。不要从运行代码反向修改数值，也不要再维护CSV或第二份Excel。

## 工作表

| 工作表 | 内容 |
| --- | --- |
| 使用说明 | 操作步骤与输入约定 |
| 全局参数 | 开局银币/日期/关系/马车，行情、补货、借贷、住宿、帮工、关系奖励、历法、事件概率与消息 |
| 商品 | 基准单价、重量、占格、堆叠、保鲜天数；保鲜0代表不计短期腐坏 |
| 城镇市场 | 每城实际经营的货物、基准售价与库存；一行是一个城镇/货物组合 |
| 商路 | 双向商路起终点、行程天数、旅费 |
| 收购公告 | 收购地点与货物、数量、单价、首次发布、截止窗口、刷新间隔 |
| 主线路标 | 售货和公告完成目标数量、银币奖励；剧情条件类型和解锁关系仍在内容文件 |
| 开局货物 | 货物数量和单件账面成本，编译时计算批次总成本 |
| 随机事件 | 持续天数范围、行程耗时倍率、库存倍率、行情倍率、每日消耗数量；名称与适用对象仍在内容文件 |

例如调整帕斯罗小麦售价：在“城镇市场”找到 `pasloe / wheat`，修改“基准售价”；需要更多收购量则在“收购公告”修改 `pazzio-wheat` 的“需求数量”。公告说明和数量展示会同时更新。

## 生效流程

1. 用 Excel/WPS 保存原生 `.xlsx`。输入直接填数字，金额用 `0.25`、`0.5`、`0.75`，不填 `¼` 文本或公式。
2. 运行 `npm run balance`。错误会指出工作表/参数或ID；校验未通过时不覆盖现有运行数据。
3. 运行 `npm run verify`，然后刷新游戏并开启新旅程。`npm start` 也会先编译；直接打开HTML只使用上次成功编译的结果。

当前存档与数值摘要绑定。有效数值变化后旧档被拒绝，要求新档；只改说明或表格外观不会改变数值摘要。

## 参数与校验

- 行情按“价格变化间隔”推进，档数为奇数，振幅决定每档偏差；市场收购率不超过100%。市场基准售价不等于当天报价。
- 每日补货为 `max(最低补货量, ceil(初始库存 / 补货除数))`，不超过该市场配置的初始库存。
- 收购截止日为 `发布日期 + 有效天数差`。截止当日可交货，次日过期；交货或自然过期之日再加“刷新间隔天”得到下一期发布日期。
- 所有金额为¼银币倍数；数量、格位、堆叠及日数为整数。重量可用小数。
- ID须唯一且与内容文件存在的定义一致；参考名称也校验，避免误改ID后仍显示另一个名字。
- 同一路线不能重复填反向一行；收购商品不能在收购地公开市场交易，且必须存在外地货源。
- 开局货物须能装进实际马车；编译器调用真实引擎验证摆放和存档一致性。
- 行商历目前固定12个月以配合四季，月长和历元日期可调；月长不得短于当前节令日期。
- 随机事件的发生概率、分类型消息提前参数、每日旅人消息概率与酒馆每次打听费用在“全局参数”的 `rules.events.*` 维护。持续天数范围、半速行进/库存翻倍/七折行情的倍率在“随机事件”维护。引擎与界面均不维护第二套参数。
- 大暴雨按每天实际生效的天气计算速度；大丰收在生效时将当日余货翻倍一次，持续期提高库存上限，结束后恢复正常上限。行情倍率同时作用于买价和收价，公告已发布的收购价保持固定。
- 城市节庆只影响目标城镇实际经营的葡萄酒、苹果和奶酪。行情倍率可高于1；每天正常补货后再扣除表内“每日消耗数量”，最低为0。与丰收重叠时行情倍率相乘，库存上限仍由丰收单独决定。事件适用商品与可信对白在内容文件维护。

编译器范围检查是引擎输入边界，不是推荐平衡区间。行为测试检查公告的外地货源、保鲜与期限可达性，以及合理运货方案的收益；不要求所有公告都能承担空车去采购的往返成本。另检查相邻商品价差、单货空返与双向配货，避免退回固定商路暴利。调参后应同步检查这些设计边界，不能删测试来掩盖问题。

## 新增内容

新增货物、城镇、公告或路标时，先在 `js/content.js` 定义稳定ID、文字与出处，再补对应表行。主线新增条件类型或新机制需要明确改引擎和编译器；只调已有数值无需改经营代码。

不要手改 `js/balance.generated.js`。它是可重建的运行产物，但必须保留在源码和离线包中，以支持直接打开HTML。

## 收购公告定价基准

公告采用经营成本加成50%的定价基准。采购本金P＝需求数量×货源市场基准售价；经营成本C＝P×单程旅途天数×贷款日利率＋单程旅费；目标净利润＝C×50%；公告货款＝P＋C×1.5。自有资金同样计机会成本，实际贷款不重复计息。按无事件、无等待的合理供货路线计算，空车前往采购的行程不计入。行情、事件和合并运货会改变实际收益，50%不是对采购本金的回报率。

保持现有单价¼银币精度：单价＝公告货款÷需求数量，四舍五入到最近的¼银币；因此实际基准利润率略偏离50%。不改变公告数量、期限、刷新或主线奖励。价格仍只维护于Excel，公式为策划定价口径，不在运行时动态重定价。
