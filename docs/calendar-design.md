查阅的公开官方资料不足以还原一套能覆盖当前旅程的完整统一历法。游戏因此采用拟制行商历，具体日期不列为原作事实。这里的结论只说明当前查证范围，不能推断作品所有卷都没有日期描写。

## 历法

| 项目 | 经营规则 |
| --- | --- |
| 名称 | 行商历 |
| 旅程第1天 | 第1年10月1日 |
| 月长 | 每月30天 |
| 年长 | 12个月，共360天 |
| 春季 | 3—5月 |
| 夏季 | 6—8月 |
| 秋季 | 9—11月 |
| 冬季 | 12月与次年1—2月 |
| 跨月例子 | 旅程第30天为1年10月30日，第31天为11月1日 |
| 跨年例子 | 旅程第90天为1年12月30日，第91天为2年1月1日 |

旅程天数作为连续时间轴；年、月、日由它换算，不跟随现实电脑时间，也不会因重新打开游戏而变化。旅行、休息和帮工会推进时间。公告发布与截止、收购再发布、食品腐坏、借贷到期、日志都引用同一时间轴。看地图、看日历、理货、阅读和查看公告不额外耗时。

## 一期收购公告的日期

每种需求在世界时间里独立运行。初期十种需求均在旅程第1天发布；城市解锁、到访、是否查看都不推迟本期的发布或截止日期。公告全地图可见，包括尚未解锁的收购地；查看不会解锁道路。

公告没有领取地，无需接单。玩家自行采购，到收购地后，只要本期仍有效并带齐自有货物，即可直接交付。公告不提供货物、不扣定金，也不收违约金。

| 字段 | 含义 |
| --- | --- |
| `initialPublishDay` | 第一次发布的旅程天数，本版为1。 |
| `listingDays` | 从发布日期到截止日的天数差；每种需求分别为6—14天。 |
| `publishedDay` | 本期实际发布日期。 |
| `dueDay` | `publishedDay + listingDays`，该日仍可交货。 |
| `refreshDays` | 本期交付或自然过期后，距离再次发布的间隔；本版统一4天。 |
| 独立发布编号 | 区分同一需求的不同期；只有当前有效编号能结算，旧编号、旧页面或重复交付不能付款。 |

例如，第1天（10月1日）发布、`listingDays = 8` 的公告，截止第9天（10月9日）。第8天（10月8日）才看到，也只剩到10月9日的时间；预先采购后直接交货，仍使用本期已有的截止日，不产生新的8天期限。

截止当天仍可交货；次日进入自然过期，公告撤下并开始冷却。没有交货的过期公告不保存为逾期任务或失败记录，也不扣钱；已成交公告可保留交付记录。公告过期或成交后，其旧编号都不能再次结算。

## 再次发布

| 情况 | 本期结束 | 下次发布 |
| --- | --- | --- |
| 10月7日交付 | 10月7日 | 10月11日，间隔4天。 |
| 10月9日截止，未成交 | 10月10日进入过期 | 10月14日，间隔4天。 |
| 10月8日查看或带货抵达 | 不改变本期周期 | 本期仍到10月9日，不提前刷新；符合条件可直接交货。 |

下一期沿用同一类需求的货物、数量与报价，同时产生新的发布编号、发布日期和截止日期。跨过多期的旅行或休息，按世界时间继续推进周期，不能在抵达时临时创建一份新截止日。交付成功后立即进入固定冷却，不能重复赚取同一份货款，也不能借旧编号交付新一期。

冷却期间可从全图公告查看下一次预计发布日期，再决定是否等待、转去别处或先备耐储货。买家收购的货物始终不在收购地的公开市场经营；商品仍须由玩家在别处购入或使用已有存货。

## 保存与版本

日期与发布周期随当前游戏状态保存。读回通过结构与数值校验的本版文件后，本期截止日、冷却、已交付记录和新旧食物批次保持原状，不根据读取时间重置期限或重新发布公告。存档只记录公告发布周期与实际成交记录。只有特雷尼银币一种货币，¼精度继续保留。

本版严格读取当前格式，拒绝旧版及校验不通过的文件，不做兼容或迁移。
